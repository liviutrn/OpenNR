## Required v01 behavior

### Sequential Feature 18 + gaze crop

- Keep the v00 gaze-history compensation fix.
- Allow 2x sequential Feature 18 while the VR NR route uses a fixed, adaptive, or eye-tracked crop.
- Pass 2 coverage is relative to the live pass-1 crop, with supported ratios 100/90/80/70/60/50%.
- A moving gaze crop remains the owner of the pass-1 center. Pass 2 is centered inside that live pass-1 region, so the two passes follow the same gaze point.
- Adaptive/FPS crop control changes pass 1 first. Pass 2 is derived from the resulting live pass-1 region every frame; it must not keep a stale absolute crop.
- No per-frame resource recreation solely because a crop origin moves.
- Ordinary crop-origin motion uses crop-motion compensation; invalid/missing-frame/large-jump/extent changes still reset history.

### Per-pass controls

Pass 1 keeps the existing NR controls. Pass 2 gets independent controls for Feature 18 tuning and result/composite behavior, including preset, intensity, tone/structure/skin, style, automask/UI correction, model/resolve controls where applicable, result shaping/stabilization, and crop-edge feather/dither parameters. Pass 2 defaults should preserve the current two-pass result unless explicitly changed.

The old experimental pre-upscale route is not part of v01 sequential operation and must not silently combine with it.

### Stereo atlas

Stereo atlas is experimental and OFF by default.

When enabled and compatible, one Feature 18 evaluation receives a horizontal atlas per sequential stage:

`LEFT | replicated-edge guard | RIGHT`

Requirements:

- normal two-eye stereo remains the fallback and A/B path;
- default central guard width: 50 output/color pixels;
- guard width is configurable and changing atlas geometry invalidates atlas temporal history;
- guard pixels replicate the adjacent eye edge rather than zero-fill;
- depth and motion guides use corresponding atlas geometry;
- atlas output discards the guard and writes only the real left/right eye regions;
- reject/fallback on asymmetric eye extents, incompatible formats/scales, invalid resource bounds, or atlas allocation/native Feature 18 failure;
- no cross-eye source sampling is permitted outside the replicated guard;
- a 2x sequential atlas target is two native Feature 18 invocations total per frame (one atlas invocation per pass), instead of four per-eye invocations.

The expected saving is primarily one native Feature 18 fixed invocation per eye pair per pass. Pixel-dependent work still covers approximately both eyes plus the guard.
